# Bug log

Source has been authored, but no implementation checks or runtime trials have
been run. No runtime defects are confirmed; all source behavior remains
unverified until the public checks have been executed.

For each issue, record ID, status, severity, affected versions and platform, scenario ID, clean-clone reproduction, expected and actual outcomes, sanitized evidence, fix reference, and verification command. Record untested platforms as coverage gaps. Link confirmed defects to the appropriate GitHub issue once the repository is public.

## Triage and updates

Before fixing a defect, search this log for a similar symptom or cause. Reuse
the prior reproduction and fix approach when it still applies. If no related
entry exists, diagnose it independently and add an entry before closing the
work. Update all affected technical documents and tests alongside the fix, then
record actual commands, results, and blockers in `docs/todolist.md`. A bug is
not verified or closed just because a patch was authored; retain its open or
unverified status until evidence supports closure.
